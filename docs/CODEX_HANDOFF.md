# Codex接手说明｜长沙摩托车通行提醒地图

## 当前项目状态

这是一个纯前端静态项目，已实现可用原型。核心文件：

- `index.html`：正式地图页面。
- `preview.html`：无高德Key的静态预览页。
- `admin.html`：点位录入助手。
- `js/app.js`：地图、筛选、弹窗、路线风险粗测逻辑。
- `js/config.js`：高德Key和基础配置。
- `data/points.json`：点位数据。
- `data/zones.json`：禁摩区域和边界道路近似线。
- `data/sources.json`：数据来源。

## 必须保持的产品口径

项目定位是“通行风险提醒/合规提醒”，不是“躲电子眼”。

禁止在页面、注释、README、标题里写：

- 躲电子眼
- 逃避抓拍
- 规避执法
- 扣分地图

建议表达：

- 禁摩区域提醒
- 边界道路提醒
- 通行风险提醒
- 待核实点位
- 以官方通告和现场标志为准

## 下一步开发优先级

### P0：修准边界坐标

1. 根据官方通告道路名，用高德地图坐标拾取工具修正 `data/zones.json`。
2. 不要只用当前近似点。
3. 每条边界道路应拆成更细的 polyline。
4. 保留 `confidence` 字段，注明“官方范围明确，坐标已按高德复核”。

### P1：CSV批量导入点位

目标：增加 `tools/import.html` 或在 `admin.html` 中支持CSV粘贴导入。

字段：

```text
id,name,type,lng,lat,direction,confidence,source,note,updatedAt
```

输出：可直接合并到 `data/points.json` 的JSON数组。

### P2：接高德路线规划API

当前路线检测是“起点到终点直线粗测”，不是路网导航。

请改成：

1. 输入起点终点。
2. 调用高德驾车路线规划API。
3. 获取路线 polyline。
4. 判断路线 polyline 距离 `points.json` 里的点位是否小于 `riskRadiusMeters`。
5. 判断路线是否穿过禁摩 `ban_area` polygon。
6. 输出风险点列表，并给出“打开高德查看路线”按钮。

注意：不要承诺“自动绕开禁摩区域”，除非实现了真实避让逻辑。

### P3：用户投稿工作流

1. 新增投稿表单。
2. 投稿只存本地或导出JSON，不直接写入正式数据。
3. 管理员审核后才合并。
4. 投稿点默认 `user_report`。

### P4：部署优化

1. 增加 GitHub Pages 部署说明截图。
2. 增加 `404.html`。
3. 增加基础SEO meta。
4. 增加PWA manifest，方便用户加到手机桌面。

## 验收标准

- 没有高德Key时，`preview.html`能正常看效果。
- 填高德Key后，`index.html`能显示真实高德地图。
- 点位筛选、搜索、弹窗、坐标复制、打开高德都正常。
- 手机端侧栏可打开/关闭。
- 路线粗测不报错。
- README里明确非官方、需现场复核。

## 品牌视觉版交接说明

用户希望项目风格贴近“骑不快的ZZ”：深蓝描边、橙色夕阳、摩托头像、普通摩友工具感。当前已将视觉统一到：

- 深蓝主色：`#17243f`
- 橙色强调：`#ff8a3d`
- 风险红色：`#e5484d`
- 背景：夕阳暖色+玻璃拟态卡片

后续Codex不要把页面改成普通政务风/纯白黑字后台风。真实高德地图只负责地图瓦片；品牌UI、卡片、筛选、弹窗、点位展示继续保留本项目样式。

下一步优先：
1. 高德Key配置校验和错误提示优化。
2. 接高德路线规划API，把直线粗测改成真实路径检测。
3. 用高德拾取器修准 `data/zones.json` 的边界坐标。
4. 增加CSV导入 `data/points.json` 的工具。
